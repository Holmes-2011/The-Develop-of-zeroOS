# v0.12-telemetry 测试记录

## 本版内容

**感知层**：让系统"看得见自己"。这是系统内置 Agent 的第一层（见 `docs/agent-design.md`）：
普通电脑上的 AI 助手只是一个普通程序，看不到内核里发生了什么；zeroOS 的内核是自己写的，
可以让每个子系统主动把自己的状态报出来。以后的系统直觉模块和诊断工具都从这里取数据。

| 改动 | 文件 |
|---|---|
| **计数器**：各条 IRQ 的次数、伪中断、键盘字符数和溢出丢弃数、kmalloc / kfree 次数和失败数、非法释放、堆已用字节（增量维护，不用遍历堆）、物理页分配 / 释放 / 非法释放、按需缺页次数、CPU 空闲时间（hlt 前后读 TSC）。中断和主循环都会加计数，用原子加 | `telemetry.c` / `telemetry.h`（新增）；`heap.c`、`pmm.c`、`keyboard.c`、`kernel.c`、`shell.c` 各加几行 |
| **采样**：时钟中断里每 100 毫秒给 18 个计数器拍一次快照，放进 256 条的环形缓冲区（约 25 秒）。在中断里做，主循环被长命令占住时也不漏采；按时间而不是按中断次数采样，以后时钟中断变快（中断风暴）也不影响间隔 | `telemetry.c` |
| **事件日志**：开机、键盘缓冲区溢出、伪中断、kmalloc 失败、非法释放（堆 / 物理页）、按需缺页、采样丢失。同类事件 1 秒内接连发生合并成一条并计数，不会刷屏 | `telemetry.c` |
| **按需分页区**：0xC0000000 起 64MB 一开始不映射；第一次访问时缺页处理程序现场分配一页、清零、映射，然后返回让那条指令重新执行，而不是停机。缺页从此成了可以观测、可以计数的信号；其他地址的缺页照旧停机 | `demand.c` / `demand.h`（新增）、`kernel.c` |
| **主循环轮询点**：命令行每次醒来先处理新采样（主循环上下文，以后的系统直觉模块在这里运行，可以用浮点） | `shell.c` |
| 新命令：`metrics`（累计值、最近 1 秒的速率、CPU 忙碌比例）、`events`、`telstream on\|off`（每次采样往串口输出一行，供采集数据用） | `telcmd.c` / `telcmd.h`（新增） |
| `memtest` 加 4 项：堆计数器和遍历整个堆的结果一致、按需分页（碰两页 → 两次缺页被处理、不停机）、释放后物理页还回去、主循环忙时采样照常进行 | `memtest.c` |
| 64 位 ÷ 32 位的除法函数公开给其他核心代码用（核心代码不能直接写 64 位除法） | `time.c` / `time.h` |
| 删除误提交的 `versions/v0.10-agent/`（和 `v0.9-memory/` 完全相同的空壳） | — |

## 测试方法

`test-boot.sh` 在 v0.11 的基础上多敲 `metrics`、`events`、`telstream on`（等 1.5 秒）、`telstream off`，并核对：

- 启动日志多一行 `telemetry sampling every 100 ms`；`help` 列出 3 个新命令
- `memtest` 22/22（原来 18 项 + 新增 4 项）
- `metrics`：时钟中断速率 80~120 次/秒；键盘字符数在涨、没有丢字符；memtest 的 2 次按需缺页被记下；CPU 忙碌比例在 0~100%（没有 TSC 时显示 n/a）
- `events`：记录了开机、memtest 故意制造的重复释放、按需缺页（2 次合并成一条）；没有采样丢失
- `telstream` 收到的约 14 次采样：表头 21 列、序号连续、间隔中位数 90~110 毫秒且 80% 以上在 80~120 毫秒、
  没有小于 50 毫秒的间隔（重复采样）、所有累计计数器只增不减、每次采样约 10 次时钟中断；
  系统闲着时 CPU 空闲比例 > 50%（没有 TSC 时恒为 0）

## 测试结果

| 测试项 | 结果 |
|---|---|
| `make` | ✅ 无警告；核心代码无浮点 / SSE / cmov；内核 46KB |
| `-M pc` 重复 | ✅ **10/10**（每次 73/73） |
| `-M q35` 重复 | ✅ **10/10**（每次 68/68：q35 没有老式 IDE 端口，少了 5 项硬盘检查） |

| Pentium III | ✅ 68/68 |
| 内存 4MB / 128MB（pc） | ✅ 69/69、73/73 |
| 内存 4GB（q35） | ✅ 68/68 |
| `telstream` 实测 | 约 14 次采样，间隔 99~102 毫秒，每次约 10 次时钟中断；闲着时 CPU 空闲比例 1.00 |

### 对照实验

故意改坏一处，测试必须失败——证明这些检查真的能发现问题，而不是怎么都通过：

| 实验 | 结果 |
|---|---|
| 去掉按需分页处理（缺页照旧停机） | ❌ memtest 第一次碰按需区就 `Page Fault ... system halted`，之后的检查全部失败（正确地失败） |
| 去掉 CPU 空闲计时 | ❌ "闲着的时候 CPU 空闲比例 > 50%" 失败，读到 0.00（正确地失败） |
| kfree 时不更新堆计数器 | ❌ memtest "heap counter matches a full heap walk" 失败（正确地失败） |

## 开发中发现并修掉的问题

| 问题 | 怎么发现的 | 修法 |
|---|---|---|
| `metrics` 里算速率用了 64 位除法，链接时报 `undefined symbol: __udivdi3` | 第一次编译 | 改用 `time.c` 里已有的 64÷32 除法（公开出来） |
| 10 次重复测试里 pc 有 1 次失败：两次采样之间隔了 281 毫秒 | 重复测试 | 不是内核的问题：Mac 很忙时 QEMU 会停顿，这段时间本来就没有时钟中断；内核记下的是真实时刻，速率按真实间隔算。测试改为看间隔的分布（中位数 + 80% 落在 80~120 毫秒），最大值只报告不判失败 |
| 测试脚本：表头列数算错（20 → 21） | 第一次运行 | 修正 |

## 已知限制

- **主循环处理采样有延迟**：长命令（`bench`、`memtest`）运行期间，采样照常进行，但要等命令结束才被处理；缓冲区 256 条（约 25 秒），超过会丢最旧的并记一条事件。
- **没有 TSC 的 CPU（486）**：CPU 空闲时间无法计量，恒为 0；时钟也退回数时钟中断。
- **按需分页区的页表**：第一次用时建的页表不回收（最多 16 张，64KB），下次接着用。
