# v0.18 测试记录

## 本版内容

**图形模式**：boot 里用 VBE 把显示切成 1024×768×32 线性帧缓冲，内核映射 LFB，
文字控制台直接画到帧缓冲；`gfx` 命令画演示画面。

| 改动 | 文件 |
|---|---|
| VBE 设模式（4F01/4F02，模式 0x144）、存 LFB 地址、拷 BIOS 8×16 字库 | `boot.asm` |
| LFB 映射到 `0xFD000000`，分辨率 / 行宽 / bpp 从 mode info 读 | `gfx.c` / `gfx.h` |
| 文字控制台同时画帧缓冲（保留 0xB8000 影子） | `console.c`、`vga.c`、`gfx.c` |
| `gfx` 命令：渐变 + 矩形 + 圆 + 标题；提示符落到画面底部 | `gfx.c`、`shell.c` |
| 测试：第六阶段用 `screendump` 抓图，`check_ppm.py` 逐像素校验 | `test-boot.sh`、`check_ppm.py` |

> boot 扇区只有 512 字节，VBE 代码加进去刚好卡满；因此内核只支持 32bpp，
> 且模式号用 QEMU 的 0x144（读 mode info 拿到的是真实宽高 / 行宽）。

## 测试结果

| 测试项 | 结果 |
|---|---|
| `-M pc` 全套 | ✅ **157/157**（含 3 项图形断言） |
| `-M q35` | ✅ 152/152（q35 的 VBE 同样可用） |
| 486（无 SSE2） | ✅ 152/152 |
| 2MB 内存 | ✅ 153/153 |
| 像素校验 | ✅ 背景条、圆、矩形三个采样点全部命中 |

### 像素断言

| 位置 | 期望值 | 含义 |
|---|---|---|
| (500, 750) | (32, 32, 32) | 底部黑色信息条 |
| (804, 220) | (204, 102, 0) | 圆的中心 |
| (100, 100) | (204, 136, 68) | 矩形填充色 |

### 关于跳过的 5 项文本屏幕检查

图形模式下 0xB8000 被 VGA 设备占用，不再是普通内存，`pmemsave 0xB8000` 读不出文本影子。
测试脚本检测到 `graphics: 1024x768x32 via VBE` 时自动跳过这 5 项，改由第六阶段的帧缓冲像素校验覆盖。
文本模式启动（VBE 不可用）时这 5 项照常执行。

## 已知限制

| 项目 | 说明 |
|---|---|
| 只有 32bpp | 24bpp（VBE 0x118）会画歪，因为行宽不是 4096；需要额外代码支持 |
| 模式号不通用 | `0x144` 是 QEMU 的编号；真机上要遍历 4F00 返回的模式列表 |
| 纯 CPU 绘制 | 没有双缓冲，全屏渐变在 486 上明显变慢 |
| 中文不支持 | 只有 BIOS 8×16 ASCII 字库 |
| 不能切回文本模式 | 运行中无法调用 BIOS，图形模式由 boot 决定 |
