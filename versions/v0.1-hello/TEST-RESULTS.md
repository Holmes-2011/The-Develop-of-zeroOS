# v0.1-hello — 测试记录

## 这一版是什么

最早的一版内核，**没有标注版本号**（上游 README 里写的 v0.1 是"清屏+停机、无任何输出"，
和这份不是同一份代码，特此说明）。

| 文件 | 大小 | 内容 |
|---|---|---|
| `kernel.c` | 1259 字节 | 文本模式：`clear_screen()` + 往 VGA 显存 `0xB8000` 写字符 |

行为：清屏，然后在第 0 行第 0 列打印

```
Hello from the C kernel, zeroOS says hi!
```

每个字符占 2 字节：第 1 字节 ASCII、第 2 字节颜色属性 `0x0F`（亮白）。

## 测试环境

QEMU 10.0.2，`-M pc`（i440FX + PIIX），32 MB 内存，显存 `0xB8000` 文本模式。

## 测试项与结果

### ① 首次真机启动 —— ❌ 失败

**现象**：屏幕只打出 `Hell` 四个字符就黑屏，然后无限重启。

**诊断过程**（读 QEMU 内存，不是靠猜）：

| 内存位置 | 读到的内容 | 含义 |
|---|---|---|
| `0x7C00` | 引导扇区原样 | ✅ BIOS 成功载入引导层 |
| `0x1000` | `e8 db 00 00 00 fa f4 eb fc` | ✅ 引导层成功把内核读进内存 |
| `0xB8000` | `48 0f 65 0f 6c 0f 6c 0f` = `H e l l` | ✅ 内核已经开始打印 |
| **`IDT`** | **`00000000 000003ff`** | ❌ **还是实模式的中断向量表** |

**根因**：引导层 `sti` 之后、进保护模式之前**没有 `lidt`**。保护模式会按"描述符"格式
解析那张实模式 IVT，全是垃圾。上电后第一个时钟中断（IRQ0，约每 55ms 一次）一到 →
取不到合法中断门 → **三重故障 → 整机重启**，循环往复。

### ② 修复后重测 —— ✅ 通过

修复：在 `boot.asm` 的 `lgdt [gdt_descriptor]` 之后补一条 `cli`（地址 `0x25`）。

```
0x20  lgdt word [0x7caf]
0x25  cli                  ← 新增
0x26  mov eax,cr0
0x2D  mov cr0,eax
0x30  jmp word 0x8:word 0x7cb5
```

| 测试 | 结果 |
|---|---|
| 连续启动 10 次 | **10 / 10 成功** |
| 屏幕显示 | `Hello from the C kernel, zeroOS says hi!` 完整 |
| 颜色属性 | 全部 `0x0F` ✓ |
| CPU 停止状态 | `EIP=0x1191  HLT=1`（内核自己的 hlt 循环） |
| 稳定性 | 间隔 4 秒两次采样，显存内容完全一致 |

**证据**：`screenshot.png`（本目录），启动后的实际画面。

## 这一版暴露的缺陷

| 编号 | 缺陷 | 后果 |
|---|---|---|
| 1 | 进保护模式前缺 `cli` | **会崩** —— 时钟中断触发三重故障重启（概率低但真实存在） |

这个缺陷从这一版一直带到 v0.3，直到后来才修掉。
