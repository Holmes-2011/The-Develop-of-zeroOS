# v0.13.2 测试记录：全量"过筛子"

## 本版内容

对 v0.6 以来的**全部内核代码**做了一次逐行复审 + 8 组专项压力测试（"过筛子"），
这一版把筛出来的问题全部修掉。运行行为对用户不变（多了 `stack_check` 工具和 `inject_fault stack_use`）。

### 筛出来的问题和修法

按严重程度排。"怎么发现"一栏区分**实测**（压力测试里真的出了错）和**复审**（读代码发现、实测里没触发过）。

| # | 问题 | 怎么发现 | 修法 | 文件 |
|---|---|---|---|---|
| ① | **堆扩张失败会吞掉物理页**：`kmalloc` 一块大内存、中途要不到物理页时，已映射的页既不在任何块里、也不会被回收。内存紧张时一次失败的大申请能把全部物理页吞光，随后系统因要不到页而停机 | **实测**：2MB 内存跑全套，`diskcheck` 的 1MB 缓冲申请失败后，`get_memory` 显示堆映射 764KB 但 0 字节在用，空闲页 0，`heap_check` 报"最后一块没到堆尾"（代码 6），接着 `demand_touch` 停机 | `grow()` 中途失败时回滚：解除本次已映射的页并还回去 | `heap.c` |
| ② | **页表页永不回收**：解除映射后空掉的页表一直占着一页。堆收缩、按需分页区释放、①的回滚之后账面总会少几页 | **实测**：修完①后 32MB 配置新自检仍差几十页；`bench` 前后页表数 513 → 516 | `paging_unmap` 发现页表全空时连页表一起释放 | `paging.c` |
| ③ | **Ctrl+C、Ctrl+Z 等组合键会打出字符**：键盘驱动不跟踪 Ctrl / Alt | **实测**：特殊键压力测试后命令行里多了 `cz` | 跟踪左右 Ctrl / Alt，按着时不产生字符 | `keyboard.c` |
| ④ | **遥测流会和正在敲的命令粘成一行**：采样行可能插在半行回显中间 | **实测**：遥测流开着时敲 150 次 `help`，266 行采样里 60 行断档、`help` 的回显 0 行完整 | 串口层记录是否在行首，机器读的行发出前不在行首就先换行；shell 只在"这一行还没敲字"时处理采样 | `serial.c`、`telemetry.c`、`shell.c` |
| ⑤ | 引导扇区不验证 A20 是否真的打开了。真机上 A20 关着时，复制内核到 1MB 会绕回写坏低端内存，现象是莫名其妙的崩溃 | 复审 | 用引导签名的回绕镜像验证；没开就再试键盘控制器方式；还不行就明确报错停机 | `boot.asm` |
| ⑥ | 内核栈溢出无法察觉（会悄悄写坏 `.bss` 里挨着栈的变量） | 复审 | 开机把栈填成图案 + 栈底哨兵；新增 `stack_check` 工具、`mem` 显示水位、`memtest` 检查哨兵 | `entry.asm`、`stack.c`（新增） |
| ⑦ | 分页初始化时若建页表就把物理页用完，会留下没映射的洞，之后在莫名其妙的地方缺页 | 复审 | 当场报错停机，说清楚卡在哪个地址 | `paging.c` |
| ⑧ | `heap_check` 遇到链表成环会死循环 | 复审 | 增加"next 往回指"检查 | `heap.c` |
| ⑨ | 中断返回前多余的 `sti`：`iret` 本来就会恢复中断标志 | 复审 | 去掉 | `isr.asm` |
| ⑩ | `keyboard_flush` 无条件 `cli`/`sti`：在关中断的上下文里调用会把中断打开 | 复审 | 改用保存/恢复式的 `irq_save`/`irq_restore`（搬到 `io.h` 共用） | `keyboard.c`、`io.h`、`telemetry.c` |
| ⑪ | `sleep` 命令睡着的时间不算空闲，`metrics` 的 CPU 忙碌比例偏高 | 复审 | 睡前后记空闲时间 | `shell.c` |
| ⑫ | `diskcheck` 范围超出盘尾时读到末尾才报"读错误"，误导 | **实测**：硬盘边界测试 | 裁剪到盘尾并说明；内存紧张时缓冲区自动退到小块 | `disktest.c` |
| ⑬ | `memcpy` / `memset` 逐字节循环 | 复审 | 改用 `rep movsb` / `rep stosb` | `kstring.c` |
| ⑭ | `inject_fault stack_use` 第一版用递归 + volatile 数组吃栈，clang 把只用了两个元素的 1KB 数组缩成了 2 字节，栈根本没被用掉 | **实测**：`stack_use 12` 后水位只涨 60 字节；反汇编确认 | 改为直接操作 esp | `builtin_tools.c` |

### 复审过、确认没有问题的

引导扇区的 LBA 读盘分块与段地址推进、E820 循环终止条件、GDT 描述符、`entry.asm` 的 `.bss` 清零顺序、
IDT 48 个门、异常错误码分类、PIC 重映射与 EOI、伪中断处理、键盘环形缓冲区的单写单读、VGA 滚屏与光标、
PIT 分频、TSC 校准与 64 位除法、物理页位图的保留顺序、堆的切分与合并、按需分页的清零、
遥测计数器的原子加、事件合并、ATA 的 LBA28/48 分支与超时、浮点代码与核心代码的隔离（静态检查：
中断两层可达范围内没有任何 SIMD 符号）、确认框的两道防线、审计环形缓冲区。

### 对照实验

| 实验 | 结果 |
|---|---|
| ① 修前：2MB 跑全套 | ❌ 堆映射 764KB / 0 在用 / 空闲页 0 / `heap_check` 代码 6 / 停机（正确地暴露） |
| ① 修后：同样场景 | ✅ 97/97，`heap_check` ok，空闲页 174 |
| 新自检"超大申请失败后内存原样"在②修前 | ❌ 32MB 上少几十页（10/10 次） |
| 同上，②修后 | ✅ 精确相等 |
| 按需分页释放检查在②修后、模拟使用里 | ❌ 10/10 失败——测试前 `demand_touch` 留下的页在另一个 4MB 区域，它的页表一并回收，比"精确相等"多 1 页。**这是自检的判据写得太死，不是内核问题**；判据改为允许多出最多 pages_before 页 |
| 堆链表故意成环 | ✅ `heap_check` 报 CORRUPT，不死循环，系统继续运行 |
| 栈底哨兵故意改写 | ✅ `stack_check` 报 OVERFLOW，`memtest` 对应两项失败 |
| ③ 修前 / 修后，30 种特殊键 | ❌ 命令行出现 `*cz` / ✅ 干净 |
| ④ 修前 / 修后，遥测流 + 60 次 `help` | ❌ 60 行断档 / ✅ 0 断档 0 粘连 |
