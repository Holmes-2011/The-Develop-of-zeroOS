# zeroOS 版本档案

这个目录按版本存放 zeroOS 的**源码 + 上游原始压缩包 + 测试结果**，一个版本一个文件夹。

当前正在开发的版本在工程**根目录**（`../`），这里是各版本的历史快照。

## 测试环境（所有版本共用）

| 项目 | 值 |
|---|---|
| 宿主机 | macOS 26.6.2，Apple Silicon (arm64) |
| 模拟器 | QEMU 10.0.2（封装自 UTM.app 内置的框架） |
| 默认机型 | `-M pc`（i440FX + PIIX，1996） |
| 兼容机型 | `-M q35`（Q35 + ICH9，2009，AHCI） |
| 内存 | 32 MB |
| 编译 | clang 21.0.0（`--target=i386-unknown-none`）+ NASM 3.02 + Zig 0.16.0 的 LLD |

## 测试方法

| 判据 | 说明 |
|---|---|
| **启动成功** | 串口依次打出该版本的全部预期行，且**只启动一次**（没有重启循环） |
| **停止状态** | CPU 停在 `HLT=1`，`EIP` 落在内核的 hlt 循环里（不是 BIOS） |
| **失败识别** | 成功的启动约 0.13 秒命中；失败的会跑满超时。两者耗时差 40 倍，不会混淆 |

> **重要**：所有"失败"结论都经过对照实验验证 —— 用**已知会失败**的样本
> （补零前的 21KB 镜像 + `q35`）喂给同一个测量脚本，确认它报 0/10，
> 才能相信它对正常样本报 100% 是真的。

## 累计发现并修复的缺陷

| # | 缺陷 | 发现方式 | 出现在 | 影响 |
|---|---|---|---|---|
| 1 | `sti` 之后进保护模式前没有 `cli`，时钟中断 → 三重故障重启 | **2×2 对照实验实测复现**（见 `v0.0.1-bootloader/`） | v0.0.1 起的引导层 | **会崩** —— 原版实测 EIP 在 10 个地址间乱跳，只有 33% 时间在内核里 |
| 2 | 镜像只有 21KB，AHCI 控制器拒绝启动 | 换机型扫描（q35 必失败） | 构建脚本 | **q35/现代硬件上完全启动不了** |
| 3 | 17/21/29/30 号异常被当成"无错误码" | 对照 x86_64 crate 的 IDT 定义 | v0.3 起的 `isr.asm` | 当前无害（异常处理不返回），将来加异常恢复会弹错返回地址 |

### 没有被实测证实的（诚实标注）

| 项目 | 状态 |
|---|---|
| 17 号 #AC 的对齐检查 | **QEMU 未实现该功能**，4 种 CPU 型号都触发不出，无法实测；修正是依规范做的 |
| 串口 0x3F8 的电气时序 | 功能正常，但波特率误差、FIFO 溢出这类**只有真机 + 示波器**能验 |
