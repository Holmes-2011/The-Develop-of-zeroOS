# v0.14-bridge 测试记录

## 本版内容

**桥接协议的内核侧**（规格：[`docs/agent-bridge-protocol.md`](../../docs/agent-bridge-protocol.md) v1）。
Mac 上的 Agent 程序通过 COM1 和 zeroOS 对话——这是 **Agent 第一次能操作 zeroOS**。

| 改动 | 文件 |
|---|---|
| 串口接收：IRQ4 + 1024 字节环形缓冲区（和键盘同一结构）；波特率 38400 → 115200 | `serial.c` / `serial.h` |
| 最小 JSON 子集：一层对象、字符串 / 无符号整数、5 种转义；就地解析；输出转义 | `kjson.c` / `kjson.h`（新增） |
| 协议：`hello` → `welcome` + 工具清单；`call` → （`confirm`）→ `result`；事件推送；`verdict` → `ack`；4 种 `error` | `bridge.c` / `bridge.h`（新增） |
| 串口来的调用走 `tools_invoke()`，`caller` = `"agent"`：权限、确认框、审计一样不少 | `bridge.c` |
| 新工具 `get_intuition`；新事件 `intuition`、`protocol error` | `builtin_tools.c`、`telemetry.c` |
| 主循环空闲时处理协议行（和采样一样只在行首）；`sleep` 期间也处理 | `shell.c` |
| 测试：`bridge_test.py` 扮演宿主机（串口和 monitor 都走 TCP），`test-boot.sh` 第二阶段自动跑它；模拟用户脚本 `soak.sh` 进仓库 | `bridge_test.py`、`soak.sh`（新增）、`test-boot.sh` |

### 安全边界（内核永远不信任串口）

- 串口只能做两件事：请求调用工具、提交直觉判断。
- **不能回答确认框**：答案只从物理键盘来；串口发来的 `y` 被当成一行坏 JSON 报错。
- **不能打开开发者模式**：`devmode` 不是工具，串口发 `call devmode` 得到 `unknown_tool`。
- `verdict` 只记录、只显示，内核不因它自动做任何事；`class` / `note` 过滤成可打印 ASCII。
- 超长行丢弃、坏 JSON 报错、版本不匹配后忽略一切直到正确的 `hello`。

## 测试方法

`bridge_test.py` 连上 QEMU 的串口（TCP），按协议走 35 步：握手与清单、6 种只读 / 错误调用、
系统级在默认模式下被拒且不弹框、破坏性调用先收 `confirm` → 串口发 y 无效 → 键盘按 n / y、
确认框期间排队的调用之后照常处理、键盘开开发者模式后重新握手看到 `devmode=1`、
系统级调用 `confirm{system}` → 键盘 y → ok、事件推送（`heap bad free`）、`verdict`（含非 ASCII 过滤、confidence 截到 100、缺字段）、
坏 JSON / 非 JSON / 未知类型 / 600 字节超长行 / 版本不匹配与恢复、转义、通过协议打开遥测流、审计里 `caller=agent`、所有 `@` 行都是合法 JSON。

### 对照实验（故意改坏内核，看 `bridge_test.py` 能不能抓到）

| 改坏什么 | 结果 |
|---|---|
| 让串口收到的 `y` 塞进键盘缓冲区（试图让串口回答确认框） | ❌ 18 项失败（正确地失败）。值得注意的是"串口发 y 不能回答确认框"那一项反而**通过**了：确认框期间内核根本不处理串口字节（结构上的第二道防线），注入的 `y` 等框结束后才进键盘缓冲区，污染了后面的所有键盘输入 |
| 系统级工具不弹框直接放行 | ❌ "默认模式 denied_by_policy" 等 4 项失败（正确地失败） |
| 不推送事件 | ❌ 34/35，事件推送那项失败（正确地失败） |
| JSON 转义漏掉引号 | ❌ 3 项失败："所有 @ 行都是合法 JSON（坏行 2）"等（正确地失败） |
| 版本不匹配也接受 | ❌ 34/35，"version_mismatch" 那项失败（正确地失败） |

### 测试中发现并修掉的问题

| 问题 | 处理 |
|---|---|
| `bridge_test.py` 第一版的接收缓冲：上一次等待在中途返回时，同一批到达的后续行留在缓冲区里，下一次等待只去 `recv` 新数据，把它们晾到再下一次——误报 2 项（"排队的调用"、"事件推送"）。用逐行调试输出确认内核行为正确、问题在测试程序 | 先吐缓冲区里的整行再 `recv` |

### 已知限制

| 项目 | 说明 |
|---|---|
| 一次只能一个未完成的调用 | 内核单线程；宿主机负责串行化 |
| 确认框期间不处理协议行 | 排队在 1024 字节缓冲区里，框结束后处理；宿主机在 `confirm` 后要多等（协议文档第 4 节） |
| 协议行只在主循环空闲时处理 | 长命令（`bench`、`diskcheck`）期间排队；缓冲区 1024 字节，超出丢弃（`serial_rx_dropped` 计数） |
| `result.output` 不保证完整 | 先转义再按 512 字节截断补 `...` |
