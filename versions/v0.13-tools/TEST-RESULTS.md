# v0.13-tools 测试记录

## 本版内容

**工具层**：Agent 能对系统做的每一件事都在这里登记成"工具"，并且只能通过 `tools_invoke()` 来做。
这是 [`docs/agent-design.md`](../../docs/agent-design.md) 权限模型的实现。
不管模型在哪里运行（2026-10-18 决定：宿主机 → 以后用户态），它都只能走这个入口。

| 改动 | 文件 |
|---|---|
| 工具登记表：名字、说明、参数、4 级权限（只读 / 可撤销 / 破坏性 / 系统级） | `tools.c` / `tools.h`（新增） |
| 权限判定：默认模式和开发者模式下每个等级直接执行 / 要确认 / 拒绝（一张表） | `tools.c` |
| **内核绘制的确认框**：黄字蓝底；只认物理键盘的 y / n；20 秒超时按拒绝；弹框前清空键盘缓冲区并注明丢了几个键 | `confirm.c` / `confirm.h`（新增） |
| 开发者模式：打开要过确认框，关闭立即生效 | `tools.c` |
| 审计日志：每次调用一条（时间、调用方、模式、工具、等级、结果、参数） | `tools.c` |
| 11 个内置工具：查询 6 个、诊断 2 个（`heap_check` / `pmm_check`）、可撤销 1 个、破坏性 1 个、系统级 1 个（`inject_fault`：heap_leak / bad_free / demand_touch / spin） | `builtin_tools.c`（新增） |
| 命令：`tools` `tool` `devmode` `audit`，以及 `sleep <ms>` | `toolcmd.c`（新增）、`shell.c` |
| 配套：`keyboard_flush()`、`heap_check()`、`pmm_check()`、`tel_clear_events()`、事件 `tool call denied` / `developer mode`、`console_set_colors()`、VGA 支持 `\r` | 各对应文件 |
| 内核大小上限 64KB → 128KB（内核已到 57KB） | `Makefile` |

### 权限表（`tools.c` 的 `decide()`）

| 等级 | 默认模式 | 开发者模式 |
|---|---|---|
| 只读 | 直接执行 | 直接执行 |
| 可撤销 | 直接执行 | 直接执行 |
| 破坏性 | 要确认 | 要确认 |
| 系统级 | **拒绝** | 要确认 |

### 确认框的两道防线

1. 弹框前 `keyboard_flush()`：之前敲进去还没处理的按键一律作废（防"提前敲好 y"）。
2. 只认 y / n，别的键忽略；20 秒没人答按拒绝。

## 测试方法

`test-boot.sh` 新增 25 项检查：只读工具直接执行、未知工具 / 参数错误的报错、破坏性工具弹框后按 n / 按 y、
系统级工具在默认模式下被拒绝、**提前敲好的 3 个 y 被丢弃**（趁 `sleep 3000` 把命令和 y 一起塞进键盘缓冲区）、
`devmode on` 要确认、开发者模式下故障注入生效且在遥测里看得见（堆泄漏、缺页、CPU 连续忙碌）、
`devmode off` 后再次被拒绝、审计日志和事件日志的内容。

## 测试结果

| 测试项 | 结果 |
|---|---|
| `make` | ✅ 无警告；核心代码无浮点 / SSE / cmov |
| `-M pc` 重复 | ✅ **10/10**（每次 100/100） |
| `-M q35` 重复 | ✅ **10/10**（95/95） |
| 486 / Pentium III / 4MB / 4GB（pc）/ 4GB（q35） | ✅ 95 / 95 / 96 / 100 / 95 |
| 确认框超时 | ✅ 20 秒无人应答 → `timeout`，审计记为 timeout |
| 确认框颜色 | ✅ 显存属性 0x1E（黄字蓝底），和正文区分 |
| 乱按 | ✅ 框里按 x 被忽略，随后的 n 生效 |

### 对照实验（故意改坏，看测试能不能抓到）

| 改坏什么 | 结果 |
|---|---|
| 确认框不清键盘缓冲区 | ❌ 提前敲好的 y 直接把破坏性工具放行了（`clear_events -> ok`），测试报错（正确地失败） |
| 权限表写坏（系统级一律放行） | ❌ 默认模式下 `inject_fault` 跑成功，测试报错（正确地失败） |
| 堆块大小多记 16 字节 | ✅ `heap_check` 立刻报 `CORRUPT code=4 at=0xD0000000` |
| 物理页释放时计数器多加 1 | ✅ 跑完 `memtest` 后 `pmm_check` 报 `MISMATCH bitmap_free=16031 counter_free=16107` |

### 测试中发现并修掉的问题

| 问题 | 处理 |
|---|---|
| 确认框的倒计时用 `\r` 回到行首重画，但 VGA 不认 `\r`，屏幕上一行行往下堆 | `vga_putc` 支持 `\r` |
| 测试脚本不会敲下划线，`get_uptime` 被敲成 `getuptime` | 下划线映射成 Shift + 减号 |
| 486 上 `bench` 瞬间返回，留不出"提前敲 y"的时间窗 | 加 `sleep <ms>` 命令，测试改用它 |
| `help` 多了 5 条命令，屏幕检查里 echo 的输出被挤出屏幕 | 屏幕快照提前一步 |

### 已知限制

| 项目 | 说明 |
|---|---|
| 串口还不能发起调用 | v0.14 加串口接收和协议；本版只有命令行能调工具 |
| 开发者模式没有物理门槛 | 设计里的"重启 + 物理按键才能开"还没做，目前只要在键盘上确认 |
| 确认框会打断正在敲的半行命令 | 行缓冲不丢，但屏幕上会被框隔开 |
| 工具只能串行 | 内核单线程；一次只有一个调用在进行 |
