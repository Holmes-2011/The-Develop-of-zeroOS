# v0.9-memory 测试记录

## 本版内容

内存管理：内核搬到 1MB 以上，有了物理页分配、分页和内核堆。这是 Agent 原型的前置条件
（JSON 解析、对话历史都需要动态内存）。

| 改动 | 文件 |
|---|---|
| 引导扇区：LBA 扩展读盘（按 64 扇区一块读，不再受 CHS 几何限制）；向 BIOS 要 E820 内存地图；进保护模式后把内核从 0x10000 复制到 1MB | `boot.asm`、`boot_info.h`（新增） |
| 内核链接到 1MB，不再受 0x1000 ~ 0x7C00（约 27KB）的限制；`KERNEL_SECTORS` 40 → 128 | `link.ld`、`Makefile` |
| 内核自己的 GDT 和 16KB 栈，不再依赖引导扇区那块内存 | `entry.asm` |
| 物理页分配：位图，每 4KB 一位；按 E820 放开可用内存，再收回保留区、1MB 以下、内核和位图本身；只用 3GB 以下 | `pmm.c` / `pmm.h`（新增） |
| 分页：恒等映射所有可用内存；**第 0 页不映射**，空指针一解引用就报错 | `paging.c` / `paging.h`（新增） |
| 内核堆 `kmalloc` / `kfree`：0xD0000000 起，按需映射新页；首次适配 + 切分 + 前后合并；魔数抓重复释放和非法指针 | `heap.c` / `heap.h`（新增） |
| 缺页异常报出访问的地址、读还是写、是否像空指针 | `kernel.c` |
| `mem` 改为显示 E820 内存地图、空闲页、分页和堆的状态；新增 `memtest` 自检命令（17 项） | `shell.c`、`memtest.c`（新增） |
| 编译选项禁用 MMX/SSE/AVX，并在链接后扫描确认内核里没有这类指令 | `Makefile` |

启动后（32MB）：内核占 `0x100000 ~ 0x108B94`，位图到 `0x10A000`，可用 7894 页，9 张页表。

## 开发中发现并修掉的问题

| 问题 | 怎么发现的 | 修法 |
|---|---|---|
| **启动即"非法指令"**：clang 默认的 i386 目标是 Pentium 4，`-O2` 把填位图、建页表的循环自动改写成 SSE 指令，但内核没开启 SSE | 第一次启动就崩在 `pmm_init`，反汇编看到 `pcmpeqd %xmm0` | `-mno-mmx -mno-sse -mno-sse2 -mno-avx`；链接后用 objdump 扫描，出现就报错（对照：去掉选项后检查报 138 条）。已发布的 v0.6.1 ~ v0.8 实测都是 0 条，不受影响 |
| **CPU 会往 GDT 里写**：加载段寄存器时 CPU 自动把描述符的"已访问"位置 1 | 大内核读盘对照实验里，内存和文件差了 1 个字节，正好在 GDT 的数据段描述符上（0x92 → 0x93） | 预先把已访问位置好；GDT 在只读数据区，以后真正设成只读时不会因此缺页 |
| 4GB 以上的内存在 `mem` 里显示成 `0x00000000 - 0xFFFFFFFF`，容易误解 | 4GB 内存测试 | 改为显示大小并注明"32 位用不到" |
| 恒等映射可能和堆的虚拟地址重叠（如果某台真机在 0xD0000000 以下还有内存） | 复查代码 | 只用 3GB（`0xC0000000`）以下的物理内存 |
| `kfree` 收到堆外指针时，打印错误信息前会先读它的块头——那个地址可能根本没映射 | 复查代码 | 先判断在不在堆里再读 |

## 测试方法

`test-boot.sh` 在 v0.8 的基础上，多敲一个 `memtest`，并核对：

- 8 行启动日志（新增物理内存、分页、堆三行）
- `memtest` 17/17 通过、没有 `[FAIL]`
- **`mem` 报的可用页数和 E820 对账**：脚本自己按 BIOS 的 E820 地图算出 1MB ~ 3GB 之间的可用页数，
  和内核报的比，差值只能是内核 + 位图占的那几页
- 内核在 1MB、分页已打开、屏幕内容（同 v0.8）

共 **31 项检查**。

## 测试结果

| 测试项 | 结果 |
|---|---|
| `make` | ✅ 无警告；无 MMX/SSE/AVX 指令；内核 16.5KB |
| `-M pc` 重复 | ✅ **10/10**（每次 31/31） |
| `-M q35` 重复 | ✅ **10/10** |
| 内存 4MB / 16MB / 128MB / 1GB / 4GB（pc） | ✅ 全部 31/31 |
| 内存 128MB / 4GB（q35） | ✅ 31/31。q35 在 4GB 时只把 2GB 放在 4GB 以下，内核正确识别（523974 页） |
| 4GB 时 4GB 以上的内存 | ✅ 被正确跳过；3GB 以下识别 786111 页、769 张页表，`memtest` 照常通过 |

### 对照实验

| 实验 | 结果 |
|---|---|
| 解引用空指针 | ✅ `Page Fault ... address 0x00000000 (read, page not mapped) -- null pointer?` |
| 写到堆末尾之外 | ✅ `Page Fault ... address 0xD0002010 (write, page not mapped)` |
| 大内核：塞 100KB 数据，256 扇区 = 4 个读盘块 | ✅ `test-boot.sh` 全过；把内存里 1MB 处的内核存下来和 `kernel.bin` 逐字节比，代码 + 只读数据 118908 字节**全部一致** |
| 堆不合并空闲块 | ❌ `memtest` 16/17，"merged back together" 失败（正确地失败） |
| 物理页分配忘了保留内核 | ❌ 页表被写到内核身上，启动卡在分页之前（正确地失败） |
| 去掉禁用 SSE 的编译选项 | ❌ 构建报 138 条 SSE 指令并停止（正确地失败） |

### 已知限制

| 项目 | 说明 |
|---|---|
| 堆只增不减 | `kfree` 释放的内存回到堆里复用，但堆映射的页不会还给物理页分配器 |
| 只用 3GB 以下的物理内存 | 32 位 + 恒等映射的取舍；以后要用更多内存需要 PAE 或改成高半内核 |
| 内核代码 / 只读数据没有设成只读 | 目前所有页都是可读写；以后可以按段设置权限 |
| 真机 | E820 和 LBA 扩展读在 2002 年以后的 BIOS 上普遍支持；纯 UEFI 启动不走这条路 |
