# v0.16 — 用户态：ring 3 + 系统调用（当前版本）

**程序第一次和内核分开跑。** 内核里嵌了两个 ring 3 程序，`run` 启动：

```
zeroOS> run
[user] hello: entering ring 3
hello from ring 3
uptime: 2010 ms
guard: kernel address rejected
tool get_uptime -> 0: uptime_ms=2071 clock=tsc timer_irqs=203
[user] exit code 0

zeroOS> run fault
[user] fault: entering ring 3
about to touch kernel memory
[user] program killed: Page Fault at EIP 0x00400011
zeroOS>
```

## 改动

| # | 改动 |
|---|---|
| ① | GDT 扩到 6 项：ring 3 代码 / 数据段（DPL=3）+ 32 位 TSS；`esp0` 指向独立的 8KB 系统调用栈 |
| ② | `int 0x80` 系统调用门（DPL=3），6 个调用：`exit` / `write` / `getkey` / `uptime` / `tool` / `sleep` |
| ③ | 用户页映射：代码 4MB 起、栈 8MB 顶，`PAGE_USER`；退出 / 被杀后释放 |
| ④ | 用户指针校验：范围 + 逐页 USER 位，非法返回 -1（`write(0xC0000000, 4)` 被拒绝） |
| ⑤ | ring 3 异常只杀程序、回 shell（以前是整机停机）；硬件中断从 ring 3 来不算故障 |
| ⑥ | 内核内嵌两个用户程序（`userprog.asm` / `userfault.asm`），`run` / `run fault` 启动 |

## 接口说明（AOS 视角）

系统调用就是内核对外的那一面：`tool` 让程序（以后是 Agent）通过同一套工具层做事，
审计里 `caller` 记成 `"user"`。v0.14 的串口协议和这里走的是**同一个 `tools_invoke()`**，
所以 B 阶段（宿主机串口）和 A 阶段（进用户态）之间接口不变。
