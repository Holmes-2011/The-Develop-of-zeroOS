# v0.15.1 — shutdown：能关机了（当前版本）

新增 `shutdown` 命令：往 ACPI 的 PM1a 控制寄存器（`0x604`）写 SLP_EN，让宿主机自己断电，
而不是像以前那样只能停在 `hlt` 循环里等人强制关掉 QEMU。

## 改动

| # | 改动 | 说明 |
|---|---|---|
| ① | `shutdown` 命令 | q35 用 16 位写 `0x3400`（ACPI 规范的 S5：SLP_TYP=5 \| SLP_EN）；pc 的 PM1a_CNT 只认字节写，高低字节各写一次（= `0x2000`） |
| ② | `io.h` 新增 `outw` | 16 位端口写，关机要用 |
| ③ | 关不掉时怎么办 | 退化成 `cli; hlt` 停机，并明确打印 "ACPI power off not available"，不假装成功 |
| ④ | 测试 | `test-boot.sh` 加第三阶段：单独起一台、敲 `shutdown`，确认 QEMU 在脚本发 `quit` 之前自己退出（ACPI 断电生效） |

## 实测

| 配置 | 结果 |
|---|---|
| `-M pc` | ✅ **143/143**（含 3 项 shutdown 检查） |
| `-M q35` | ✅ **138/138**，ACPI 同样能关 |
| 486 / 2MB / 1GB / q35 4GB | ✅ 全绿 |
| 模拟用户 10 轮 | ✅ 0 异常 0 失败 |

> 关不掉的机器（真机、或 ACPI 表不对的芯片组）不会卡死：打印一行说明后停机。
> 现在的机器上只有 QEMU 验证过，真机上的 ACPI 关机没有测过。
