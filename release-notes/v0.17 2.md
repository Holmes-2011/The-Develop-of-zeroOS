# v0.17 — 抢占式调度：后台任务和命令行同时跑（当前版本）

`run` 不再卡住命令行：它创建一个后台任务就立刻返回。时钟每 10ms 打一次 tick，
任务之间按 30ms 时间片轮转；shell 在等键盘时把 CPU 让出去，一有按键马上回来。

```
zeroOS> run loop
[task 1] started in background; type 'jobs' to list
zeroOS> tick
tick
tick
zeroOS> echo alive
alive
zeroOS> jobs
  1  loop  ready
[task 1] loop exited, code 0
zeroOS>
```

## 改动

| # | 改动 |
|---|---|
| ① | 调度器：任务表、轮转、抢占、僵尸回收；`sched_idle()` 让 shell 在空闲时让出 CPU |
| ② | `switch_to`：保存 / 恢复内核栈 + callee-saved 寄存器；每个任务独立 8KB 内核栈，`TSS.esp0` 跟随任务 |
| ③ | 浮点上下文：FXSAVE / FXRSTOR（486 这种没有 FXSR 的 CPU 自动跳过） |
| ④ | 用户程序改成位置无关（`call/pop` 取基址），每个任务 16MB 虚拟窗口，互不重叠 |
| ⑤ | `run` 变后台任务；新增 `jobs` / `kill` |
| ⑥ | `exit` / ring 3 异常改成 `sched_exit()`，不再回到旧栈 |

## 调度策略

```
时钟 tick（10ms）
  └─ 当前是用户任务？
       ├─ 键盘缓冲区有输入 → 切回 shell（命令行优先）
       └─ 时间片用完（30ms）→ 轮转到下一个 ready 任务
内核（shell）不被时钟抢占：它在等键盘时主动调用 sched_idle() 让出 CPU。
```

## 测试

| 配置 | 结果 |
|---|---|
| `pc` | ✅ **160/160**（含 9 项调度器断言） |
| `q35` / 486 / 2MB | ✅ 155 / 155 / 156 |
| 模拟用户 10 轮 | ✅ 0 异常 0 失败 |

调度器阶段验证了：后台任务启动、任务跑的时候命令行照常响应、`jobs` 列出运行中任务、
任务正常退出、`kill` 掉任务并回收、缺页任务被杀而 shell 存活、全部任务结束后 `memtest` 26/26。

## 已知限制

- 内核不抢占：shell 执行命令时后台任务暂停（命令都很短）。
- 输出会交错：没有 per-task 控制台，打字时能看到 tick 插在中间。
- 纯轮转，没有优先级；`kill` 要等下一次调度才生效。
