# v0.21 — 第一次联网：virtio-net + ARP/IPv4/ICMP/UDP/DNS（当前版本）

这一版让 zeroOS 能真的发包收包了：`ping` 能通，`dns` 能解析域名。
**还没有 TCP/TLS，也没有浏览器**——这是网络的第一层地基。

## 改动

| # | 改动 | 文件 |
|---|---|---|
| ① | legacy virtio-net 驱动：I/O BAR、队列握手、RX/TX 环 | `virtio_net.c` / `.h` |
| ② | 以太网 / ARP（请求 + 应答 + 缓存） | `net.c` |
| ③ | IPv4（首部 + 校验和）、ICMP echo | `net.c` |
| ④ | UDP + DNS 查询/解析（A 记录） | `net.c` |
| ⑤ | 命令：`net` / `ping <ip>` / `dns <name>` | `shell.c` |
| ⑥ | 测试：第十阶段起 QEMU user-net，`ping 10.0.2.2` | `test-boot.sh` |

## 实测

```
zeroOS> net
mac: 52:54:00:12:34:56
ip:  10.0.2.15/24  gw: 10.0.2.2  dns: 10.0.2.3
link: up (gateway resolved)

zeroOS> ping 10.0.2.2
reply from 10.0.2.2: time=1 ms

zeroOS> dns example.com
example.com -> 104.20.23.154
```

|---|---|
| pc（带 virtio-net） | ✅ 166/166（新增 3 项网络断言） |
| 无网卡 | ✅ 正常启动，`net` 报无设备 |
| q35 | 未跑网络阶段（USB/网络阶段都只在 pc 跑） |

### 踩到的坑

1. **legacy virtio 的 queue size 是设备只读的**（QEMU 是 256），不能按 64 写死；used ring 的偏移要按设备大小算。
2. `net_init()` 里 ARP 等待用了 `hlt`，必须放在 `sti` 之后，否则永远醒不过来。
3. `arp_resolve(ip, NULL)` 时缓存命中会往空指针写 MAC —— 加判空。

## 现在能做什么 / 不能做什么

| 能做 | 不能做 |
|---|---|
| 配置静态 IP（10.0.2.15/24） | DHCP（地址写死） |
| ARP、ICMP ping、DNS A 记录 | TCP、HTTP、TLS |
| 收发原始以太网帧（驱动层） | 浏览器、下载文件 |

下一步（v0.22）才会做：TCP 握手 + HTTP GET + FAT 落盘 + 下载命令。
浏览器仍然不在近期范围内。
