# v0.15 — 高半内核：给用户态腾出 0 ~ 3GB（当前版本）

内核从虚拟地址 `0x100000` 搬到 `0xC0100000`，物理内存整体映射到 `0xC0000000` 起。
对用户的行为不变；目的只有一个：**0 ~ 3GB 的虚拟地址空出来，v0.16 的用户态程序才有地方放。**

## 改动

| # | 改动 | 说明 |
|---|---|---|
| ① | 链接地址 `0xC0100000` | 加载地址仍是物理 1MB（`AT(...)`）；入口汇编建临时页表、开分页、跳到高地址 |
| ② | 分页拆开物理 / 虚拟 | 页表访问经 `P2V()`；`paging_init` 建直接映射窗口后换 CR3，临时表作废；低 3GB 一页不映射 |
| ③ | 地址空间重排 | 物理窗口 `0xC0000000` 起（上限 768MB）；堆挪到 `0xF0000000`；按需分页区挪到 `0xF8000000` |
| ④ | 所有碰物理页的代码改经 `P2V()` | 页表、按需分页清零、物理页自检、显存、E820、位图 |
| ⑤ | `memtest` 新增 2 项 | 显存经窗口可达；`0xB8000` / `0x100000` 等低地址确认不再映射（26/26） |
| ⑥ | 测试脚本跟上新地址 | 缺页事件 `0xC0…` → `0xF8…`；E820 对账只算 768MB 窗口 |

### 虚拟地址布局

```
0x00000000 ~ 0xBFFFFFFF  用户态（现在空着；第 0 页永远不映射）
0xC0000000 ~ 0xEFFFFFFF  物理内存直接映射：虚拟 = 物理 + 0xC0000000，最多 768MB
0xF0000000 ~ 0xF7FFFFFF  内核堆
0xF8000000 ~ 0xFBFFFFFF  按需分页区
0xFC000000 ~ 0xFFFFFFFF  留着
```

## 测试

| 测试项 | 结果 |
|---|---|
| `pc` 32MB / `q35` 32MB（含桥接协议 35 步） | ✅ 140/140、135/135 |
| 486（无 SSE2） | ✅ 135/135，`memtest` 26/26 |
| 2MB / 1GB / q35 4GB 内存 | ✅ 136/136、140/140、135/135；1GB 以上正确截到 768MB 窗口 |
| 模拟用户 10 轮 | ✅ 0 异常 0 失败，`memtest` 10/10，空闲页回到初值 |

## 升级提示

- 物理内存上限从 3GB 降到 **768MB**（直接映射窗口宽度）；更大的机器只能用到前 768MB。
- 内核堆、按需分页区的虚拟地址变了，**之前基于 `0xD0000000` / `0xC0000000` 写的代码或脚本要改**：
  堆 → `0xF0000000`，按需分页区 → `0xF8000000`。
- 命令行、工具层、桥接协议的行为都没变。
