# v0.5 — PIC 重映射 + IRQ 入口

新增 **8259 PIC 重映射**，把硬件中断号从 BIOS 默认的 0~15 **挪到 32~47**，
避开和 CPU 异常号（0~31）撞车（比如 IRQ0 定时器默认会撞上 8 号"双重故障"异常）。

> 所有 IRQ 此时**仍然全部屏蔽**、IF 也没打开 —— 这一步只是把地基搭好，
> 为以后写定时器/键盘驱动做准备。

## 内容

| 文件 | 大小 | 说明 |
|---|---|---|
| `kernel.c` | 5045 | 加 PIC 重映射调用，`isr_handler` 区分异常/硬件中断 |
| `idt.c` | 5110 | IDT 门扩展到 0~47（新增 16 个 IRQ 门） |
| `isr.asm` | 2803 | 新增 `irq0`~`irq15` 入口桩 |
| `pic.c` / `pic.h` | 1344 / 827 | `pic_remap` / `pic_send_eoi` / `pic_mask_all` |
| `io.h` | 499 | `inb` / `outb` 公共函数 |
| `test-boot.sh` | 2018 | 上游自带的自动化测试脚本 |

## 测试结果（本项目测试最充分的一版）

| 测试项 | 结果 |
|---|---|
| 启动（4 行串口） | ✅ `pc` 和 `q35` 都通过 |
| IDT 门 32~47 是否指向 `irq0`~`irq15` | ✅ 16 个逐个对上，flags 全 `0x8E` |
| PIC 屏蔽寄存器实际值 | ✅ `0x21` 和 `0xA1` 都是 `0xFF` |
| **32 个 CPU 异常向量逐个触发** | ✅ **32 / 32 名字全部正确** |
| **真实 #GP**（非法段选择子）的错误码路径 | ✅ `err=0x44 eip=0x1DD1 cs=0x08`，三个字段全对 |

## ⚠️ 这一版查出的缺陷（已在 v0.5.1 修复）

`isr.asm` 把 **17 / 21 / 29 / 30** 号异常标成了 `ISR_NOERRCODE`，
但 CPU 真实触发这 4 个异常时**会多压一个错误码**。

**依据**：Intel SDM Vol.3A 6.3.1 / AMD APM Vol.2 8.4.2 的异常表。
压错误码的向量共 10 个：`8, 10, 11, 12, 13, 14, 17, 21, 29, 30`。

| 后果 | 说明 |
|---|---|
| 当前 | **无害** —— 异常处理函数直接停机、**永不返回**，那条 `iret` 到不了 |
| 将来 | 一旦加上"恢复现场/杀掉任务"的能力，这 4 个会从错位 4 字节的栈上弹返回地址 |
